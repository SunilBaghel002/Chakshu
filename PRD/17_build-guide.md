## 1. The four rules that do the most work

If you remember nothing else:

1. **One primary per viewport.** `primaryOwner` context. Two amber filled bars on screen is the single most common cause of "this looks amateur" (`ui-console.md` L4).
2. **Slots, not divs.** `<Slot id="SLOT-02" h={44}>`. No hand-rolled layout divs. Passing an unknown id throws in dev.
3. **Sticky footers.** `position: sticky; bottom: 0` inside the panel, opaque `--panel` background, 1 px `--line` top border. This alone removes the "everything jumps" feeling.
4. **Disable, never hide.** Every disabled control carries one of the eight reason strings from `ui-controls.md` §1.5. Silent disabling is a bug.

## 3. `Slot.tsx` (8.2) — the shape that works

```tsx
// components/layout/Slot.tsx
export function Slot({ id, children }: { id: SlotId; children: React.ReactNode }) {
  const spec = SLOTS[id];
  if (import.meta.env.DEV && !spec) throw new Error(`Unregistered slot: ${id}`);
  return (
    <section
      data-slot={id}
      style={{ height: spec.h, zIndex: 'var(--z-sticky)' }}
      className="w-full border-b border-line bg-panel"
    >
      {children}
    </section>
  );
}
```

`lib/slots.ts` is generated by hand from `ui-console.md` §4 — one entry per slot with `{ h, w, collapse, allowedChildren }`. If the doc and the file disagree, **the doc wins and you correct the file** (`ui-console.md` §8.2).

**Slot dimensions to get exactly right:** SLOT-00 `18`, SLOT-01 `56`, SLOT-02 `44`, SLOT-05 `56 × main`, SLOT-20..26 `380 × main`, SLOT-30 `72`, SLOT-40 `24`. Nothing in 00/01/02/40 ever changes height; the map well absorbs all resize (`ui-console.md` §6).

## 4. `Button.tsx` (8.3) — the only button renderer

Seven variants (`primary` `secondary` `ghost` `danger-outline` `danger-filled` `icon-ghost` `bar`), three sizes (`sm` 28 / `md` 36 / `lg` 44), seven states.

```tsx
export function Button({ variant, size = 'md', state, reason, ... }) {
  const { owner, claim } = usePrimaryOwner();
  const downgrade = (variant === 'primary' || variant === 'bar') && owner !== null;
  if (import.meta.env.DEV && downgrade) console.warn(`Second primary in viewport; downgrading.`);
  const v = downgrade ? 'secondary' : variant;
  return (
    <button
      type="button"                              /* never <div onClick> */
      aria-busy={state === 'loading'}
      aria-disabled={state === 'disabled'}
      title={reason ? DISABLED_REASONS[reason] : undefined}
    >…</button>
  );
}
```

Three details that are easy to get wrong and are explicitly specified:

- **`loading`** = label switches to the gerund (`DETECT` → `DETECTING`) + a 2 px indeterminate bar along the button's **bottom edge**. **No spinner inside a button** (`ui-controls.md` §1.3).
- **`focus-visible`**, not `:focus`. 2 px amber ring, `outline-offset: 2px`. Never `outline: none` without a replacement.
- **Labels are typed in sentence case** (`Detect changes`) and uppercased with `text-transform`, so screen readers behave. Strings come from `lib/copy.ts`.

**The eight reason strings** (`ui-controls.md` §1.5) — `no-aoi` `SELECT AN AOI FIRST` · `no-dates` `BOTH DATES REQUIRED` · `same-date` `DATES MUST DIFFER` · `job-running` `ANALYSIS IN PROGRESS` · `offline` `UNAVAILABLE OFFLINE` · `no-selection` `SELECT A TARGET FIRST` · `gate-failed` `RESOLUTION BELOW 2 m — SEE NOTICE` · `permission` `ADMIN ONLY`.

## 5. MapLibre (8.20) — what changes from Leaflet

This is the largest single task in Phase 8 and the one most likely to overrun.

**Delete:** `npm uninstall leaflet @types/leaflet`. Remove `satelliteProviders.ts` entirely and the Leaflet CSS link at `index.html:10`.

**Rewrite, do not patch:** `components/MapPane.tsx`, `lib/useMapPolygons.ts`, `lib/map-fx.ts`, `lib/satelliteFallback.ts`.

**What MapLibre gives you that Leaflet cannot** (`code-standards.md` §1.3):

```ts
const map = new maplibregl.Map({
  container: el,
  style: '/api/v1/tiles/style.json',   // served by the backend, not a CDN
  navigationControl: false,            // SLOT-12 zoom stack replaces it
  attributionControl: { compact: true },
});
map.addControl(new maplibregl.AttributionControl({ compact: true }), 'bottom-left');
```

**M3 lock-on is the signature interaction** — build it last, after everything else works, so you can debug it against a stable map. Its requirements are exact (`ui-context.md` §6 M3): stroke → `--amber-hot` 2 px, fill 30%→45%, four corner brackets animating from 12 px outside the bbox inward over **160 ms staggered 30 ms**, dossier tag sliding 8 px over **140 ms** skewed −2°, **400 ms count-up on the polygon's area**, and a 1 px leader line. Hovering the *tag* must keep the lock — no flicker at the boundary.

**Hard constraint:** the count-up fires **only for `MEASURED`**. Animating an `INFERRED` value dresses a guess as a measurement (`ux-rules.md` §7.1).

**Open item:** `brand/ui-prototype-intel.html` is not in the repo, and `ui-context.md` §11.4 makes it the tie-breaker for M1–M10 timings. Until it arrives, `ui-context.md` §6 is the only source. Do not invent one.

## 6. The mistakes this rebuild exists to fix

From `ui-console.md` §7, each with the rule that prevents it:

| If you see this | You violated |
|---|---|
| Buttons floating over imagery | SLOT-10 is overlays only, ≤ 220 px, four insets |
| Two amber primaries visible | `primaryOwner` |
| Panel buttons move when content grows | sticky footer |
| Numbers jitter as values change | tabular numerals + fixed column widths |
| Icon-only buttons with no label in panels | icon-only allowed in SLOT-05/12/40 + row actions only |
| Zoom control duplicated | `navigationControl: false` |
| Attribution colliding with the readout | reserved bottom-right 300 × 40 |
| Random 13 px / 7 px gaps | tokens; lint bans arbitrary values |
| `z-index: 999` | the §2 ladder |
